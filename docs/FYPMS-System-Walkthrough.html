1. Executive Summary

FYPMS is a full-stack web application that helps universities manage Final Year Projects (FYP). It connects four stakeholder roles — Student, Advisor, Coordinator, and Admin — through a single portal.

What the system does

  • Registers students and organizes them into project groups
  • Assigns projects and advisors to groups
  • Tracks submissions (proposals, reports, presentations) with file upload
  • Schedules advisor meetings and records evaluations/grades
  • Sends notifications when events occur
  • Provides reports and audit logs for administrators
  • Supports English and Arabic UI with light/dark themes

Request flow (live mode)

  1. User signs in via Supabase Auth on the frontend
  2. Frontend receives a JWT access token
  3. Every API call includes Authorization: Bearer <token>
  4. Backend JwtAuthGuard validates the token with Supabase
  5. PermissionsGuard checks role-based permissions (RBAC)
  6. Service layer applies data scoping (user sees only their data)
  7. Response returned as JSON with consistent envelope

Data scoping rules

  • Student — sees only their group, project's submissions/meetings/grades
  • Advisor — sees only groups/projects assigned via project_advisor table
  • Coordinator / Admin — sees all records; can mutate groups, projects, departments

7. End-to-End Project Lifecycle

Phase 1: SETUP (Coordinator/Admin)
──────────────────────────────────
Create Departments → Create Projects
       ↓
Register Students → Form Groups → Assign Members + Leader
       ↓
Assign Project to Group → Assign Advisor(s) to Project

Phase 2: ACTIVE PROJECT (Student + Advisor)
────────────────────────────────────────────
Student submits Proposal → Advisor reviews
       ↓
Advisor schedules Meetings → Students notified
       ↓
Student submits Progress Reports → Advisor reviews
       ↓
Advisor records Evaluation grades → Publishes → Students notified

Phase 3: COMPLETION
───────────────────
Final submission approved → Project status: Completed
       ↓
Reports & Audit log available to Admin/Coordinator

Status transitions

Projects: Pending → Approved → Ongoing → Completed (or Rejected / Archived)

Submissions: Pending → Approved | Rejected | RevisionRequired

8. Role-Based Walkthroughs

8.1 Student Flow

  1. Login as student1@fypms.test
  2. Dashboard — project, group, supervisor, next meeting, grades
  3. Projects — view assigned project only
  4. Submissions — upload files; track review status
  5. Meetings — view scheduled meetings (read-only)
  6. Evaluations — view published grades only
  7. Notifications — unread badge; mark as read

Journey: Dashboard → Submissions → Upload → Notifications (reviewed) → Evaluations (grades)

8.2 Advisor Flow

  1. Login as advisor@fypms.test
  2. Dashboard — assigned projects, meetings, pending submissions
  3. Groups — view assigned groups only
  4. Submissions — review (approve/reject/revision)
  5. Meetings — create meetings (notifies students)
  6. Evaluations — record and publish marks

Journey: Submissions (review) → Meetings (schedule) → Evaluations (grade & publish)

8.3 Coordinator / Admin Flow

  1. Login as coordinator@fypms.test or admin@fypms.test
  2. Dashboard — institution-wide statistics
  3. Groups — create, manage members, assign projects
  4. Projects — full CRUD
  5. Departments — manage departments
  6. Reports — summaries and charts
  7. Audit — system activity log

9. Module-by-Module Flow

9.1 Submissions

Student uploads file → status: Pending
Advisor reviews → Approved / RevisionRequired / Rejected
                → Notification sent to group
                → Audit log entry created

API: POST /submissions/upload · GET /submissions · PUT /submissions/:id/review

9.2 Meetings

Advisor creates meeting for assigned group → students receive notification → audit logged.

API: POST /meetings · GET /meetings/group/:groupId

9.3 Evaluations

Admin/Coordinator manage rubric templates. Advisors record group marks and publish. Students see published grades only.

API: GET /evaluations · POST /evaluations/group · PUT /evaluations/group/:id

9.4 Groups

Coordinator creates group → adds students → assigns one project per group.

API: GET /groups · POST /groups/:id/members · POST /groups/:id/project

9.5 Reports & Audit

Admin/Coordinator access aggregated reports and audit trail of system mutations.

10. API & Security Model

  • RBAC — each endpoint requires specific permissions
  • Scoping — findAllForUser / findByIdForUser filters data per role
  • Reference API — GET /reference returns role-safe lookup data
  • Smoke tests — automated tests for all 4 roles + negative access checks
